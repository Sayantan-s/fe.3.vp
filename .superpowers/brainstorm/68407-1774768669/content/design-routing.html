Design — Section 1: Routing & File Structure

New route structure under /studio/[id]

File Structure
src/app/
├── page.tsx → redirect to /studio/test-d-123 (or landing)
├── layout.tsx → root layout (unchanged)
└── studio/
└── [id]/
├── layout.tsx → providers + slot composition
├── loading.tsx → full-page skeleton fallback
├── error.tsx → full-page error boundary
├── page.tsx → empty (children slot, can be null)
├── default.tsx → fallback for children slot
├── @leftPanel/
├── page.tsx → renders LeftPanel component
├── loading.tsx → left panel skeleton
├── error.tsx → left panel error
└── default.tsx
├── @rightPanel/
├── page.tsx → renders RightPanel with lazy Player
├── loading.tsx → right panel skeleton
├── error.tsx → right panel error
└── default.tsx
└── api/video/[id]/ → unchanged

Layout Composition

studio/[id]/layout.tsx (simplified)
// Server Component — reads [id] from params
// Wraps slots in client-side providers

export default function StudioLayout({
leftPanel,
rightPanel,
params,
}) {
const { id } = await params;
return (
<StudioProvider videoId={id}>
<main className={styles.root}>
{leftPanel}
{rightPanel}
</main>
</StudioProvider>
);
}

Key Decisions

  • Layout is a Server Component — reads [id] from params, passes to client-side StudioProvider
  • page.tsx is empty/null — the children slot has nothing to render; all content lives in the parallel slots
  • default.tsx files required for each slot + children to handle hard navigations
  • Root page.tsx redirects to /studio/test-d-123 (or whatever the default ID is)
