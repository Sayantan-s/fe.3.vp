Architecture Approaches

Code splitting, context architecture, and parallel routes for the video studio

A

Full Parallel Routes — 3 Slots

Structure: /studio/[id]/layout.tsx with @leftPanel, @rightPanel, and @transcript as separate parallel route slots

Context: Layout provides VideoDataStateContext + VideoDataActionsContext + TranscriptStateContext + TranscriptActionsContext. Both APIs fetched concurrently in a shared hook, state split across domains.

Player: Lazy loaded via React.lazy + Suspense inside @rightPanel. Receives padding/rounding/bg/videoUrl as controlled props from context consumer.

Skeleton: Each slot gets its own loading.tsx for route-level skeletons, plus Suspense fallbacks for the lazy player.

Pros

  • Maximum code splitting — 3 independent bundles
  • Clean architectural boundaries at the route level
  • Each slot gets independent loading/error via Next.js conventions
  • Transcript panel is fully isolated for future work

Cons

  • 3 slots adds routing complexity — need default.tsx for each
  • Transcript slot is mostly empty right now (placeholder)
  • Left panel layout (transcript above, controls below) harder to achieve across 2 separate slots
B

Two Parallel Routes — Left + Right Slots

Structure: /studio/[id]/layout.tsx with @leftPanel and @rightPanel. Transcript stays as a component inside @leftPanel (not its own slot).

Context: Same 4-context split (VideoData state/actions, Transcript state/actions). Layout provides all contexts.

Player: Lazy loaded inside @rightPanel. Controlled by VideoData context values.

Skeleton: @leftPanel/loading.tsx and @rightPanel/loading.tsx for route-level skeletons. Additional Suspense boundary around lazy Player.

Pros

  • 2 clean bundles — left panel vs right panel
  • Left panel layout stays natural (transcript + controls in one flex column)
  • Simpler routing — 2 slots instead of 3
  • Transcript still isolated via context, can become its own slot later
  • Matches the visual layout: sidebar | main

Cons

  • Transcript not code-split from controls (both in @leftPanel bundle)
  • Less granular than 3-slot approach
C

Two Parallel Routes + Nested Parallel for Transcript

Structure: /studio/[id]/layout.tsx with @leftPanel and @rightPanel. Inside @leftPanel, a nested layout with @transcript and @controls as sub-slots.

Context: Same 4-context split. Top layout provides all contexts.

Player: Lazy loaded inside @rightPanel. Controlled props from context.

Skeleton: Route-level skeletons at both levels. Transcript and controls can load independently within the left panel.

Pros

  • Maximum isolation — transcript, controls, and player are all separate bundles
  • Left panel layout preserved via nested layout
  • Each sub-component can have its own loading/error boundary

Cons

  • Most complex routing setup — nested parallel routes
  • Overkill given transcript is a placeholder right now
  • Harder to reason about for future developers

Recommendation: Approach B — it gives you the code splitting and architectural separation you want with minimal routing overhead. When transcript becomes real, promoting it to its own slot is a small diff.
